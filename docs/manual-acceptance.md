# DevDock 人工验收单

这份清单用于验证已实现的功能。测试包准备了项目、命令、本地 Git 远程仓库和异常场景；你主要需要点击按钮、观察结果、记录是否通过。所有验收结果先留空，**准备好场景不代表你已经验收通过**。

先打开验收包中的说明页，再双击 `01-启动主验收.cmd`。入口使用独立配置；第 1–7 节的项目与远程仓库都在验收包内，Push 只上传到本机测试远程。第 8 节连接真实 GitHub，创建仓库和 Push 会改变所选账号下的测试仓库。套件根目录：`{{SUITE_ROOT}}`；双击 `06-打开验收目录.cmd` 可以打开它。请按下面的顺序操作；提交、移除项目、清除历史会改变后续可观察的状态。

结果栏填写 `通过`、`失败` 或 `未测`。遇到失败，记下编号、实际表现和截图即可；不要为了继续测试而修改自己的真实项目。需要重来时，双击 `07-生成新一轮.cmd`，新一轮数据与旧一轮分开。`00-人工验收.html` 可勾选结果、填写备注并导出报告；启动应用请双击对应的 `.cmd` 文件。

## 已准备的项目

| 项目 | 已准备的内容 | 主要用途 |
| --- | --- | --- |
| `01-workflow` | 有上游的 Git 仓库；修改、新文件、删除、二进制文件，以及同一文件的暂存和未暂存改动；测试、构建、持续运行与辅助按钮 | 正常开发流程、命令、日志 |
| `02-first-push` | 已有提交和本地远程，尚未关联上游 | 首次 Push |
| `03-commit-rejected` | 有意拒绝提交的 Git hook；另有关闭该 hook 的按钮 | 提交失败、说明保留、修复后重试 |
| `04-push-rejected` | 本地和远程各有不同提交；另有模拟远程新增提交的按钮 | Fetch、非快进推送拒绝 |
| `05-non-git` | 普通文件夹与子目录、命令 | 非 Git 项目、工作目录 |
| `06-conflict` | 尚未解决的合并冲突 | 冲突提示、阻止提交 |
| `07-unborn` | 尚无提交，也没有 remote 的 Git 仓库 | 首次提交、无远程提示 |
| `08-remove-me` | 可移除的独立项目 | 移除不删除磁盘文件 |
| `09-add-me` | 已放在磁盘上，尚未注册到面板 | 文件夹选择、手动添加、命令识别 |
| `10-git-setup` | 尚未注册、尚未初始化 Git 的普通文件夹；独立 Test / Build 示例 | 仓库初始化、身份、账号、远程配置与首次上传 |

主验收配置的唤出键是 **Ctrl + Alt + Shift + D**。请以面板底部显示的组合为准；修改快捷键后也要使用新组合。恢复、损坏配置、历史数量等独立场景使用各自入口，不与主验收配置混用。

| F13 | 没有任务时从托盘“退出”，重新启动；再打开同一主验收入口一次。 | 正常退出后可重开；同一配置的第二次启动唤出已有窗口，不出现两个主窗口。 | ____ |

本版的“−”是**收起为工具条**，× 是**隐藏到托盘**；没有单独的最小化按钮，因此不要把它们验收为最小化功能。

## 7. 重启保存与独立恢复场景

先完成主配置保存检查，再退出主验收应用，逐个使用说明页中的独立入口。一个场景检查完就正常退出，再启动下一个；这些场景不应覆盖主验收记录。第一次启动的“损坏”场景会把坏文件备份，因此后续重开不会重复第一次的提示。

| 编号 | 操作 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| G01 | 在主配置选 `05-non-git`，保留一个自建按钮，修改置顶/通知，移动并调整普通面板尺寸；正常退出再重开。 | 当前项目、按钮及其工作目录、偏好、普通面板尺寸/位置和历史保留；选项目不报 EXDEV。 | ____ |
| G02 | 收起为工具条，正常退出后重开，再展开。 | 紧凑偏好保留；展开后普通面板尺寸合理，不变成工具条的高度。 | ____ |
| G03 | 双击 `02-启动中断恢复.cmd`，看准备好的历史记录；退出。 | 该记录从预置的 running 转为“已中断”，日志说明上次退出未完成；应用没有启动任何对应进程。**这是预置状态恢复演练，不是一次真实崩溃记录。** | ____ |
| G04 | 双击 `03-启动历史损坏.cmd`；观察提示，运行一个命令，再退出。 | 启动提示历史格式损坏及备份位置；项目和命令仍在；`profiles` 内对应配置的坏 history.json 被保留为 `.corrupt-…bak`，新任务可产生正常历史。 | ____ |
| G05 | 双击 `04-启动配置损坏.cmd`；观察提示，添加 `{{ADD_PROJECT_PATH}}`，退出并重开该入口。 | 首次显示备份提示及空项目欢迎页；坏 config.json 被保留；新添加的项目可以保存并重启恢复。此场景使用默认快捷键，若它被普通版 DevDock 占用，应有快捷键警告，不能把该警告当成配置恢复失败。 | ____ |
| G06 | 双击 `05-启动历史容量.cmd`；先看预置的 99 条历史，然后分别运行 Test 和“输出中文”，每次等结束；正常退出再重开此入口。 | 重开后显示最近 100 条：预置记录 001 被移除，002 至 099 和两次真实运行保留。**标有“样例”的 99 条是模拟数据，只有你点击的两次是本轮实际执行。** | ____ |
| G07 | 退出独立场景，重新打开主验收入口。 | 主配置中的项目、设置和未清除的历史仍在；恢复演练没有覆盖它们。 | ____ |

## 8. 仓库与账号（0.2.0 新增）

从 `01-启动主验收.cmd` 打开新版。已验证的私有 GitHub 仓库及本地项目位置见验收目录中的 `联网验证说明.md`；已准备联网入口时，可双击 `08-启动联网验收.cmd` 查看 `{{ONLINE_PROJECT_PATH}}`。下面 H01 从独立的 `10-git-setup` 开始，主验收原有项目保持不变。远程的连接测试检查读取权限；实际 Push 检查写入权限。

| 编号 | 操作 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| H01 | 添加 `{{GIT_SETUP_PROJECT_PATH}}` 文件夹，点击面板上的“初始化 Git”（也可从设置进入“仓库与账号”）；保留初始分支 main，点击“初始化 Git”。 | 普通目录变为 Git 仓库；原有文件保留，出现提交身份和远程配置入口。 | ____ |
| H02 | 填写姓名与邮箱，点击“保存提交身份”；返回面板再打开设置检查。 | 身份在当前项目保存；修改不会更改其他项目或全局 Git 身份。 | ____ |
| H03 | 查看 GitHub 账号卡片，点击“刷新账号状态”。已登录时点击“使用 GitHub 身份”。 | 显示当前账号；姓名与 GitHub 隐私邮箱写入当前项目。本次联网验证使用的账号是 {{ONLINE_ACCOUNT}}。 | ____ |
| H04 | 在远程区域点击“添加远程”，名称填 local-check，地址填 `{{LOCAL_CHECK_REMOTE}}`，保存后点“测试连接”。 | 远程新增且连接成功。若 B01 尚未推送，显示空仓库；若已执行 B01，则显示已有分支，均不应误报为登录失败。 | ____ |
| H05 | 编辑 local-check，改名 local-edited；保存，再移除，分别验证取消和确认。 | 改名成功；取消保留、确认移除。项目文件和本地提交仍在。 | ____ |
| H06 | GitHub 账号卡片选择“选择已有仓库”→ 加载仓库，选择 `{{ONLINE_REPOSITORY}}`，远程名称填 origin，连接。 | 已有私有仓库成功关联；地址不包含密码或令牌。这里只验证关联和读取，此新建本地项目尚未同步远程历史，不要直接向已有 main 推送。 | ____ |
| H07 | origin 的“测试连接”；查看返回结果。 | 已认证读取成功，并能识别远程分支；提示写权限仍需实际 Push 验证。 | ____ |
| H08 | 在“创建新仓库”填写未使用的测试名称与说明，观察默认可见性；先将远程名称保留 origin。 | 默认私有。已有 origin 时创建按钮不可用，不能覆盖现有远程。 | ____ |
| H09 | 将新仓库远程名称改为 fresh-origin，再点“创建私有仓库并连接”。填写的新名称需尚未被账号使用。 | 在当前 GitHub 账号下创建一个私有空仓库并关联；尚未点击 Push 时不会上传文件。 | ____ |
| H10 | 回面板 Test → Commit 暂存并提交；首次 Push 选择 fresh-origin 与 main，再点“推送并关联上游”。 | 提交和上传成功，下次 Push 已有上游；GitHub 网页能看到本次提交与文件。 | ____ |
| H11 | 添加与现有远程同名的远程；再尝试地址 `ext::echo bad`。 | 重复名称和不支持的地址分别给出明确错误；已有远程不被覆盖。 | ____ |
| H12 | 打开“创建新仓库”，远程名称填 `bad.lock`，其余填合法值，点击创建。 | 本地立即提示远程名称无效，不会在 GitHub 创建一个无法关联的多余仓库。 | ____ |
| H13 | 在远程区域添加名为 missing 的地址，指向套件下不存在的路径；测试连接，然后移除。 | 保存地址后测试显示连接失败及原因；应用保持可操作，其他远程仍存在。 | ____ |
| H14 | 正常退出并重开新版，再进“仓库与账号”。 | 提交身份、远程和 GitHub 登录仍可读取，账号令牌不出现在 DevDock JSON 配置中。 | ____ |
| H15 | 在尚未登录 GitHub CLI 的环境中点击“登录 GitHub”，观察验证码并在浏览器授权；也可在授权前点“取消登录”。当前机器已有登录，可将此项记为未测。 | 登录可由面板发起，完成后自动显示账号；取消停止等待。无需将密码或令牌粘贴到 DevDock。 | ____ |
